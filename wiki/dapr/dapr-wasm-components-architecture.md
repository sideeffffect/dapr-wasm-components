# dapr-wasm-components — Architecture & Decisions

> Sources: this repository (components/wit/, components/, e2e/, .github/), 2026-06-11 (v2 redesign, same day as v1); wasi-grpc provider added 2026-06-12; repository restructure + world rename 2026-06-13

## Overview

Pure-wasm modules: the **interface** WIT package `dapr-wasm-components:interfaces` (`wit/`, published to OCI as `dapr-wasm-components-interface`) and two **implementation** components exporting every interface — `dapr-wasm-components-wasi-http` (`components/wasi-http/`, the Dapr HTTP API via `wasi:http` outgoing requests, portable to any WASI 0.2 runtime) and `dapr-wasm-components-wasi-grpc` (`components/wasi-grpc/`, the Dapr gRPC API via tonic over Spin's outbound HTTP/2 — Spin ≥ 3.4 only, see below). Apps import the interfaces, get composed with an implementation (`wac plug`), and run next to a Dapr sidecar.

## v1 → v2: why the redesign

v1 (same day) used a native wasmtime host bridging to the Dapr Rust SDK. v2 replaced it on request: the implementation must be pure wasm so *anyone* can compose against it without a custom host. The Rust SDK (tokio/tonic gRPC) cannot compile to wasm32-wasip2, so it was dropped entirely — the HTTP protocol is implemented directly. Bonus: no longer limited to what the SDK supports; the **whole** outbound API surface including alpha (lock, crypto, state query/transactions, jobs, conversation, workflow management, actors client) is covered.

## Key decisions

- **Sync WIT, blocking wasi:http.** Interfaces stay synchronous (user preference, WASI 0.2). The implementation uses `wstd`'s HTTP client with `wstd::runtime::block_on` inside sync exports — wasi:http polling blocks the guest, no async ABI needed.
- **WIT package name is `dapr-wasm-components:interfaces`** — `interface` (singular) is a reserved WIT keyword and cannot be a package name. OCI artifact names are exact (`dapr-wasm-components-interface`, `dapr-wasm-components-wasi-http`) because publishing uses `wkg oci push` with explicit references (also required for the `latest` tag — `wkg publish` only accepts semver tags).
- **Outbound only.** Inbound flows (pub/sub delivery, input bindings, job triggers, actor hosting, config watches) arrive on the app's HTTP app channel → apps export `wasi:http/incoming-handler`. No callback interfaces in the WIT.
- **`dapr-server` world exports `types` explicitly** so composition leaves no dangling `types` import in the composed component. (World names: `dapr-client` = imported by apps, `dapr-server` = exported by providers — renamed from `imports`/`provider` on 2026-06-13; see *Repository structure*.)
- **HTTP-faithful interface shapes**: invocation exposes verb/headers/status passthrough; state has transactions and query (possible over HTTP, impossible via the Rust SDK); errors map HTTP status classes to the `error` variant (400 invalid-argument, 401/403 permission-denied, 404 not-found, 409/412 aborted, 5xx internal, transport unavailable).
- **JSON value convention**: HTTP state/bindings APIs carry values as JSON. Bytes that parse as JSON are embedded as-is; otherwise sent as a JSON string (UTF-8 lossy). Response strings are returned unquoted so text roundtrips.
- **Config via env** (read inside the component through `wasi:cli/environment`): `DAPR_HTTP_ENDPOINT` → `DAPR_HTTP_PORT` → `http://127.0.0.1:3500`; `DAPR_API_TOKEN` → `dapr-api-token` header.
- **Workspace split** (three Cargo workspaces): the root native workspace holds `e2e/` only; `components/` (the two providers) and `e2e/apps/` (the demo apps) are separate **wasm-only** workspaces — guest crates don't build natively. Root `Cargo.toml` `exclude`s both. Nesting the `e2e/apps/` workspace inside the `e2e` member package is fine: Cargo only reads a member's own `Cargo.toml`, never descends into sibling subdirs, so the nested `[workspace]` is independent (verified via `cargo metadata`).
- **Testing without Dapr**: `e2e/` runs the real provider in wasmtime (wasmtime-wasi-http supplies real outgoing HTTP) against a mock axum sidecar, asserting recorded requests; plus a composition test that plugs kv-demo into the provider with **wac-graph** (programmatic `wac plug`) and runs the composed command via `wasmtime_wasi::p2::bindings::Command`.
- **Testing with real Dapr** (`e2e/tests/dapr.rs`, `#[ignore]`d, CI job `dapr-e2e`): two wasm microservices through two actual daprd 1.18 sidecars — `checkout` (command) publishes to Redis pub/sub; `order-processor` (wstd `#[wstd::http_server]` component served by `wasmtime serve -S cli --env ...`) receives deliveries on its app channel, declares programmatic subscriptions via `/dapr/subscribe`, CAS-increments a state counter (etag + first-write), and answers `summary` service invocations. Cross-sidecar name resolution: the **sqlite** nameresolution component (shared db file via daprd `--config`) — deterministic in CI, unlike mDNS. State: `state.in-memory` per sidecar. daprd quirks handled: per-sidecar `--dapr-grpc-port`/`--dapr-internal-grpc-port`, `--enable-metrics=false` (default metrics port would clash between two daprds). **Trap**: spawning daprd with piped stdio and not draining the pipes deadlocks daprd mid-startup once the pipe buffer fills — drain with reader threads. All infrastructure comes from **testcontainers**: Redis (`testcontainers-modules` redis + blocking feature) and both daprd sidecars (`GenericImage` `daprio/daprd:<tag>` — no entrypoint, binary at `/daprd`, runs as user 65532). Containerized daprd works with `.with_network("host")` (so it can dial the host-side `wasmtime serve` app channel and our test can reach its API ports) plus a bind mount of the shared dir (resources, config, sqlite nameres db) — the dir must be chmod 0777 for the non-root container user, and the sqlite connectionString must use the **container** path. wasmtime stays a host CLI (it runs the wasm under test). Future testcontainers candidates: `daprio/placement` (would unlock actors E2E) and `daprio/scheduler` (jobs triggers), both needing more app-channel protocol in the wasm services. **Trap**: the `wasmtime.dev/install.sh` script can fail resolving "latest" *and* exit 0 — pin the version and download the release tarball directly in CI.
- **OCI publishing**: `wkg oci push ghcr.io/sideeffffect/<module>:<tag>` with `org.opencontainers.image.source` annotation for repo linking. Tag `latest` on pushes to main; on GitHub releases the tag is the release version, and CI fails if it doesn't match the WIT package version in `components/wit/types.wit`. **Only the three published artifacts** (interface + wasi-http + wasi-grpc) are pushed — the `e2e/apps/` demo apps never are. (Earlier `dapr/client` and `dapr/kv-demo` ghcr packages were v1 leftovers, slated for deletion; v2 CI never publishes them. `wkg wit build --wit-dir components/wit` still reads `wkg.toml` from the repo root CWD, so wkg.toml stays at root.)

## Repository structure (2026-06-13)

Tightened the boundary between "what we publish" and "what only exists to test it":

- **`components/` = only the three published things** — `components/wit/` (the WIT package, moved from the repo-root `wit/`), `components/wasi-http/`, `components/wasi-grpc/`. The demo/fixture apps (`kv-demo`, `order-processor`, `checkout`, `spin-demo`) moved to **`e2e/apps/`** (their own wasm-only workspace), since they are the e2e suite's fixtures. Relative WIT paths: providers use `path: "../wit"`; demo apps use `path: "../../../components/wit"`.
- **World rename**: `imports` → **`dapr-client`** (an app imports these to *call* Dapr — the app is the client), `provider` → **`dapr-server`** (a provider exports these to *implement* the API — the component-model server side). Names now describe the *role*, not the import/export mechanism. wasmtime's `bindgen!` derives the struct name from the world, so `bindings::Provider` became `bindings::DaprServer`. World renames don't affect composition — `wac plug` matches interface identifiers (`dapr-wasm-components:interfaces/state`, …), not world names.
- **Two communication directions** (now documented in the README): these components implement **only outbound** (app → Dapr) — the `dapr-client`/`dapr-server` interfaces, transported as HTTP (wasi-http) or gRPC (wasi-grpc). **Inbound** (Dapr → app: pub/sub deliveries, bindings, invocation handlers, job/actor/config callbacks) does *not* go through any provider — the app exports `wasi:http/incoming-handler` and the sidecar calls it over a plain HTTP app channel. The two directions are orthogonal and independently configured: a wasi-grpc app calls Dapr over gRPC yet still receives events over HTTP. (A gRPC app channel is possible in Dapr but would require the app to implement the `AppCallback` gRPC service; HTTP is what every WASI 0.2 runtime can serve.)
- **CI**: builds `e2e/apps/` alongside `components/` (fmt + clippy + build for all three workspaces), validates `kv-demo.wasm` from `e2e/apps/target/`, and still publishes only the three modules. `e2e/src/lib.rs` resolves provider artifacts under `components/target/` and demo-app artifacts under `e2e/apps/target/` (the `app_path` vs `provider_artifact` split).

## The wasi-grpc provider (PoC, 2026-06-12)

Built on Fermyon's `wasi-grpc` 0.1.0 crate, accepting the Spin-only constraint deliberately (see [gRPC to Dapr from Wasm](dapr-grpc-from-wasm.md) for why it isn't portable). Key decisions and traps:

- **Stack**: tonic 0.13.1 (`default-features=false, features=["codegen","prost"]` — transport never compiles to wasm, codegen does) + `wasi-grpc` (a `tower::Service` bridging tonic to `wasi-hyperium`'s wasi:http outgoing path) + **`spin_executor::run` as the sync bridge** — it's pure `wasi:io/poll` polling (deps: futures, once_cell, wasi=0.13.1; no Spin host imports), the exact analogue of wstd's `block_on` in the wasi-http provider. Composition isolation means the provider's executor lives in its own component instance — no clash with the app's wstd reactor.
- **wasm32-wasip2 works** even though Fermyon's examples build wasip1 — that's convention, not requirement. `wasm-component-ld` semver-merges the `wasi` 0.13.1 crate's `@0.2.0` imports up to the toolchain's WASI version; the composed component carries dual-version wasi imports (provider @0.2.4/0.2.6, wstd app @0.2.9) and **Spin resolves both** via wasmtime's semver-compat export/import matching.
- **Protos vendored, codegen checked in** (like the Dapr Rust SDK): `components/wasi-grpc/proto/` holds dapr/dapr v1.18.0 protos, `src/proto/` the generated client — generated once with **protox** (pure-Rust protoc replacement), so neither protoc nor a build script is needed. v1.18 split dapr.proto into per-block files; `dapr.proto` imports `appcallback.proto` (messages reused by streaming subscribe), so it must be in the compile set.
- **h2c is exact-match, single-authority, host-process-scoped**: `SPIN_OUTBOUND_H2C_PRIOR_KNOWLEDGE` holds ONE `host:port` compared byte-for-byte against the request URI authority; it must be set on the `spin up` process (NOT `spin up --env`, which only sets guest env), and must textually equal the `DAPR_GRPC_ENDPOINT` authority. Spin's http trigger accepts any `wasi:http/incoming-handler@0.2.x` and tolerates the app's extra `wasi:cli/run` export.
- **RPC choices**: stable names over deprecated Alpha1 where v1.18 has both (BulkPublishEvent, GetConfiguration, ScheduleJob/GetJob/DeleteJob); workflow uses the Beta1 set (Alpha1 carries `option deprecated`); lock/crypto/state-query only exist as Alpha1. Crypto's bidi streams are driven one-shot (single request message carrying options + whole payload, then half-close, reassemble by seq). JSON-in-proto payloads (job data, conversation parameters) pack as `Any(google.protobuf.Value)` (`anyjson.rs`).
- **gRPC semantic gaps vs HTTP** (documented in README): SaveState has no request-level metadata (folded into per-item metadata); GetState/GetActorState can't distinguish missing from empty (empty data+etag → `none`); InvokeService can't pass through the app's status code (200 on success, non-2xx → `error`) and headers ride as gRPC metadata; no gRPC health service in daprd — `GetMetadata` is the readiness ping; `grpc-status` codes map 1:1 to the WIT error variant (cleaner than HTTP status classes); a missing secret surfaces as `internal` (ERR_SECRET_GET), not `not-found`.
- **daprd gRPC quirks verified against daprd 1.18 source** (adversarial review): actor invoke metadata keys are case-sensitive — use lowercase `content-type`; daprd packs actor reminder data as `Any(google.protobuf.BytesValue)` (unpack it — raw `Any.value` is protobuf-framed) **and** the gRPC register path base64-wraps the data via Go `json.Marshal([]byte)`, so gRPC-registered reminder callbacks see base64 where HTTP-registered ones see the JSON (inherent, daprd ≤ 1.18); conversation parameters use protojson wrapper Anys (`{"@type": ".../Int64Value", "value": "100"}`) — pack the documented wrapper types, not just `Value`; `ConversationMessageOfTool.name` is a plain proto3 string (empty is wire-valid — don't reject tool-role messages); crypto accepts options+payload in one first message with `seq: 0`, capped by MaxRequestBodySize (default 4Mi) per gRPC message.
- **E2E** (`e2e/tests/spin.rs`, CI job `spin-e2e`): spin-demo + provider composed by wac-graph, served by the spin CLI (which doubles as the daprd app channel — programmatic subscription, delivery routes, invocation echo), daprd 1.18 testcontainer (host network, in-memory state + in-memory pubsub — no Redis needed for a single sidecar). Asserts byte-exact binary state + etag CAS + delete, invoke-out-and-back-in, publish→deliver→count. **Trap**: `spin up` runs the server as a `spin trigger http` *subprocess* — killing the parent leaks the trigger and its port; spawn with `process_group(0)` and kill the group. **Trap**: ports in Docker's ephemeral range (32768+) can collide with stray docker-proxy mappings (testcontainers ryuk held 50053 for hours) — daprd then dies at bind; use ports below 32768. **Trap**: `pkill -f` patterns can match your own shell wrapper's command line and kill it mid-script.
- Spin CLI install: pinned tarball `github.com/spinframework/spin/releases/download/v4.0.1/spin-v4.0.1-linux-amd64.tar.gz` (same pin-don't-trust-latest policy as wasmtime); readiness via the built-in `/.well-known/spin/health`.

## Known limitations

- Crypto is one-shot (no streaming); conversation is the alpha2 text subset (no tool calls); configuration subscribe not exposed.
- Alpha Dapr APIs can break between Dapr releases; the version-prefix map lives in [Dapr HTTP API](dapr-http-api.md).
- Binary (non-JSON) state values don't roundtrip byte-exact (JSON-string encoding).
